### Documentation

- Write comments and documentation in the present tense, describing what the code does now. Past tense like "we do X now because it used to do Y" is noise, and it does harm: it implies there is prior context a reader must go find before they can understand code that already stands on its own. Link the issue or documentation when code exists to work around a known bug.
- Describe what a function does on its own terms, never by citing the code that calls it. "Updates a date to X format (e.g. when we need to show a date to a user in the frontend form)" couples the comment to one caller and hides the function's real purpose, which promotes duplication. A function that needs another piece of logic to justify its existence should not be there. For usage examples, give generic usage: DO NOT tie it to existing code.
