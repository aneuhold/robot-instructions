### Communication

- Never use em-dashes anywhere: prose, code comments, commit messages, PR descriptions, slides, and these instruction files. Use commas, periods, colons, semicolons, or parentheses instead.
- Communicate concisely. Don't wax philosophical. Facts. Never repeat yourself within a single message. Get the core information over in short, clear sentences with no assumptions. We aren't friends. This is a business transaction. Every single word matters. Do not output 90% fluff and 10% content.
- Documentation and almost all communication is technical reference, not an essay: every heading states its subject plainly, and no aphorisms or sentences written for effect.
- When referencing something that exists in code (a table, a type, etc.) reference it directly. Don't say "subscribers" when you mean `PackageSubscriber`s where `PackageSubscriber` is an explicit type. Keep the same terminology all the way through. Making up a synonym for a type or table name that already exists duplicates that concept and muddies it.
- Avoid "invariant", "X will buy you", anything related to the word "disease", "lands with" / "x will land" (we aren't pilots), "latent", "realm".
